设置窗口的音频页面用来选择声音从哪里输出，以及录音从哪里输入。用 选项 › 音频设置... 打开。设置向导（选项 › 设置向导（语言、音频、插件文件夹）...）也会测试音频输出。

让声音出来

  1. 打开 选项 › 音频设置...。
  2. 选择一个 驱动程序。下拉框下方的说明会告诉你这种驱动程序适合什么情况。
  3. 选择一个 输出设备。
  4. 点击 播放测试音。
  5. 查看 状态 部分。它会显示正在运行的驱动程序、采样率和输出延迟，或者显示 未打开音频设备：请选择输出设备。。

驱动程序

驱动程序 下拉框列出你系统上的驱动程序类型。

系统驱动程序作用
WindowsWindows音频（共享）其他程序的声音不受影响。Windows 以固定步长混合所有程序的声音，所以缓冲区不能小于这个步长
WindowsWindows音频（共享，低延迟周期）仍是共享模式，但会向 Windows 请求更短的混合周期。只有部分驱动程序支持
WindowsWindows音频（独占，最低延迟）LYNX SHARE 独占设备。播放时其他程序没有声音
WindowsDirectSound（旧版）旧的 Windows 音频通道，延迟高。其他方式都不行时再用
WindowsASIO低延迟驱动程序。厂商的 ASIO 驱动程序配合它自己的设备使用
WindowsLYNX ASIO（内置）LYNX SHARE 自带的 ASIO 驱动程序，适用于任何设备，支持播放和录音。驱动程序设置... 用来选择共享或独占模式以及设备
macOSCore Audio系统自带的音频，与其他程序共享
LinuxPipeWire（原生）LYNX SHARE 直接与 PipeWire 通信。System default 跟随系统声音设置中选择的输出
LinuxJACK / PipeWire用于正在运行的 JACK 服务器，或装有 pipewire-jack 的 PipeWire
LinuxALSA直接与声卡通信。default 或 pipewire 共享设备，hw: 设备则让 LYNX SHARE 独占声卡

在 Linux 上，首次启动时会打开 PipeWire、JACK、ALSA 中第一个有设备的驱动程序。保存过的选择会保留。

没有声音时

  • 先看 状态。如果没有打开任何设备，请选择一个输出设备。
  • 换一个驱动程序试试。在 Windows 上，Windows音频（共享） 可以让其他程序保留声音，而 DirectSound（旧版） 是在其他方式都不行时使用的。
  • 检查混音台中的主控推子，以及工具栏中的 主控 旋钮。
  • 在样式模式下，只会播放当前样式。如果它是空的，就什么也听不到。按 L 切换到歌曲模式。
  • 在 Linux 上，如果声音断断续续，状态 会显示音频线程是否获得了实时优先级。解决办法见故障排除。

须知

  • ASIO 只存在于 Windows。
  • 使用 Windows音频（共享） 时，最小缓冲区就是系统的混合步长。驱动程序 下拉框下方的说明会给出你的设备的具体数值。要获得更低的延迟，请使用独占模式或 ASIO 驱动程序。
  • 使用 PipeWire 时，缓冲区范围是 32 到 2048 个采样，采样率范围是 44.1 到 192 kHz。如果 PipeWire 保持自己的采样率，它会对 LYNX SHARE 的音频流重新采样。
  • 使用 PipeWire 时，如果拔掉了指定名称的设备，LYNX SHARE 会回退到 System default，并保持缓冲区大小不变。
  • 状态 还会显示音频 CPU 负载，并统计掉帧次数（缓冲区欠载）。
  • 不打开窗口也可以列出驱动程序和设备。见命令行中的 --devices。
