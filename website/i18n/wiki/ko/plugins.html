LYNX SHARE는 다른 제작사의 악기와 이펙트 플러그인을 호스팅합니다. 플러그인 폴더를 스캔해서 플러그인을 찾으며, 옵션 › 플러그인 관리자... 메뉴에서 찾은 목록을 볼 수 있습니다. LYNX SHARE 자체 악기와 이펙트는 내장 악기와 이펙트에 설명되어 있습니다.

플러그인 스캔하고 추가하기

  1. 옵션 › 플러그인 스캔 메뉴를 선택합니다. 진행 상황이 힌트 바에 표시되며 그동안 작업을 계속할 수 있습니다.
  2. 플러그인이 별도의 폴더에 있다면 옵션 › 플러그인 관리자... 메뉴를 열고 플러그인 폴더... 버튼을 클릭해 폴더를 추가한 다음 새 플러그인 찾기 버튼을 클릭합니다.
  3. F8 키를 눌러 플러그인 선택기를 열고 플러그인 이름의 일부를 입력합니다.
  4. 더블 클릭하거나 Enter 키를 누릅니다. 악기는 새 채널이 되고, 이펙트는 선택한 믹서 인서트에 들어갑니다.

처음 시작할 때 설정 마법사가 플러그인 폴더를 나열하고 백그라운드에서 스캔합니다. 옵션 › 설정 마법사(언어, 오디오, 플러그인 폴더)... 메뉴에서 다시 열 수 있습니다. LYNX SHARE는 시작하고 몇 초 뒤에도 새 플러그인을 찾아봅니다.

시스템별 형식

시스템호스팅하는 형식
WindowsVST3, CLAP, VST2
macOSVST3, CLAP, Audio Units
LinuxVST3, CLAP, LV2, VST2

macOS에서는 VST2를 호스팅하지 않습니다. Linux에서는 직접 설치하는 yabridge와 Wine을 통해 Windows 플러그인이 동작합니다. yabridge가 동기화하는 폴더를 플러그인 폴더로 추가하세요.

각 플러그인 파일은 별도 프로세스에서 검사합니다. 충돌하거나 30초 동안 멈춘 파일은 실패로 표시되고 이후에는 건너뜁니다. Windows에서는 실패한 파일이 이유와 함께 %APPDATA%\LYNX\scan-failures.log에 나열됩니다.

표준 폴더와 사용자가 추가한 폴더를 스캔합니다.

  • Windows: Common Files\VST3, Common Files\CLAP, Common Files\VST2, Program Files 아래의 VSTPlugins와 Steinberg\VSTPlugins, 그리고 FL Studio가 설치되어 있으면 FL Studio가 쓰는 폴더.
  • macOS: ~/Library/Audio/Plug-Ins와 /Library/Audio/Plug-Ins의 VST3, Components, CLAP.
  • Linux: ~/.vst3, ~/.clap, ~/.lv2, ~/.vst, 그리고 /usr/lib와 /usr/local/lib 아래의 같은 폴더.

플러그인을 별도 프로세스에서 실행하기

기본적으로 플러그인은 LYNX SHARE 안에서 실행되므로, 충돌하는 플러그인 때문에 프로그램이 종료될 수 있습니다. 옵션으로 플러그인마다 자체 프로세스에서 실행할 수 있습니다.

  1. 옵션 › 일반 설정... 메뉴를 엽니다.
  2. 플러그인을 별도 프로세스에서 실행(충돌로부터 LYNX SHARE 보호) 옵션을 켭니다.
  3. 이미 열려 있는 플러그인에 적용하려면 프로젝트를 다시 엽니다.

이런 플러그인이 충돌하거나 응답을 멈추면 뮤트되고 메시지가 나타나며 LYNX SHARE는 계속 실행됩니다. 프로젝트를 저장하고 다시 열면 플러그인이 다시 로드됩니다. 플러그인의 에디터는 자체 창에서 열립니다.

플러그인 하나에만 적용하려면 플러그인 창의 래퍼 메뉴에서 별도 프로세스에서 실행 또는 Always run <plugin> in a separate process 항목을 선택합니다. 플러그인의 에디터가 충돌했을 때 나타나는 메시지에서도 두 번째 항목을 제안합니다.

Windows와 Linux에서 동작하며, macOS에서는 0.1.25부터 동작합니다.

32비트 플러그인(Windows 전용)

Windows에서 32비트 VST2와 VST3 플러그인은 브리지(LYNX-bridge32.exe)를 통해 실행됩니다. 브리지는 레이턴시를 더하지 않습니다. 브리지 안에서 충돌한 플러그인은 혼자 멈추고 LYNX SHARE는 계속 재생합니다. 브리지된 플러그인의 에디터는 자체 창에서 열립니다. 플러그인의 32비트 빌드와 64비트 빌드가 모두 설치되어 있으면, 플러그인 창의 래퍼 설정 항목에 있는 비트 크기 옵션으로 어느 쪽을 로드할지 정합니다.

도구 › 플러그인 성능 모니터... 메뉴를 선택하면 모든 악기와 이펙트가 차지하는 처리 시간이 현재, 평균, 최대로 나열됩니다. 100%는 오디오가 지속되는 내내 프로세서 코어 하나가 가득 차 있다는 뜻입니다.

플러그인이 설치되어 있지 않을 때

LYNX SHARE는 같은 플러그인을 식별자로 먼저 찾고, 다음에 파일로, 그다음에 이름으로 찾습니다. VST2로 저장한 프로젝트는 같은 제품의 VST3로 열리고 그 반대도 마찬가지이지만, 이때 플러그인은 기본 설정으로 재생됩니다.

이펙트가 아예 설치되어 있지 않으면 같은 역할을 하는 LYNX SHARE 이펙트가 슬롯을 대신하고 원본은 프로젝트에 남습니다. 내장 악기와 이펙트를 참고하세요. 도움말 › 누락된 파일... 메뉴에는 대체된 플러그인이 나열됩니다.

알아 두면 좋은 점

  • 호스팅된 플러그인의 창에는 프리셋 바가 있습니다. 플러그인 자체 프로그램, 사용자의 프리셋, 프리셋 저장..., 프리셋 파일 불러오기..., 프리셋 파일 내보내기...이 있습니다. .fxp, .fxb, .vstpreset 파일은 별도 프로세스가 아니라 LYNX SHARE 안에서 실행되는 플러그인에만 로드됩니다.
  • 모니터는 창이 열려 있는 동안에만 측정합니다.
  • 누락된 악기는 아직 대체되지 않습니다. 누락된 악기 플러그인은 채널 이름에 따라 고른 내장 신스가 됩니다.
