Файл › Открыть... (Ctrl+O) открывает собственные проекты .lynx LYNX SHARE, а также файлы .flp, .als, .flm и .mid. Проект из другой программы импортируется: он становится новым несохраненным проектом LYNX SHARE, а исходный файл никогда не перезаписывается.

Открытие проекта из другой программы

  1. Выберите Файл › Открыть... и укажите файл .flp, .als, .flm или .mid.
  2. Подождите, пока LYNX SHARE ищет плагины и сэмплы проекта.
  3. Если что-то не найдено, открывается окно Отсутствующие файлы. Укажите в нем, где лежат ваши сэмплы, либо закройте его.
  4. В заголовке окна теперь показано, откуда взят проект, например «(imported from FL Studio)».
  5. Выберите Файл › Сохранить. LYNX SHARE спросит, куда записать файл .lynx.

Сторонние плагины VST2, VST3 и CLAP в .flp, а также плагины VST2 и VST3 в .als загружаются с сохраненным состоянием, если тот же плагин установлен на вашем компьютере.

Собственные плагины FL Studio

Генераторы и эффекты FL Studio не загружаются. LYNX SHARE читает их сохраненные настройки и играет их на воссозданных движках. У каждого движка есть уровень качества: от Exact (побитово совпадает с оригиналом во всех проверенных состояниях) до Placeholder (настройки сохраняются, но плагин молчит или пропускает звук без обработки). Уровни объяснены в статье Переход с FL Studio.

Открытие .flp работает и без установленной FL Studio. Некоторым движкам нужны волны, сэмплы или импульсы, которые во время работы читаются из вашей собственной установки FL Studio.

Отсутствующие сэмплы

Вкладка Сэмплы перечисляет все ненайденные сэмплы с сохраненным путем и тем, что их использует.

КомандаЧто делает
Папка поиска...Ищет все отсутствующие сэмплы в папке и ее подпапках
Найти...Спрашивает, где лежит один сэмпл. Остальные, найденные в той же папке, подхватываются тоже
ПропуститьПропускает сэмпл. Его канал остается беззвучным

Применить использует найденные файлы.

На вкладке Найдено автоматически перечислены файлы, которые LYNX SHARE сам нашел в другой папке. Сохраните проект, чтобы запомнить новые места.

Отсутствующие плагины

LYNX SHARE ищет каждый сторонний плагин сначала по идентификатору, затем по файлу, затем по имени. Проект, сохраненный с VST2, открывается с VST3 того же продукта и наоборот, но уже с настройками по умолчанию.

Если эффект не установлен, его слот занимает эффект LYNX SHARE с той же ролью: реверб вместо реверба, компрессор вместо компрессора.

  • В слоте показано имя оригинального плагина со значком LYNX SHARE.
  • Если сохраненное состояние удается прочитать, настройки переносятся. Иначе замена стартует с пресета по умолчанию. Таблица продуктов, их замен и того, что переносится для каждого, находится в PLUGIN_FALLBACK.md.
  • Автоматизация параметров оригинала сохраняется, но не управляет заменой.
  • Ссылка на оригинальный плагин и его состояние остаются в проекте. Когда плагин будет установлен, проект снова откроется с ним.
  • Байпас всех замен LYNX SHARE в проекте в контекстном меню слота замены отключает их все сразу.

Включает это Заменять отсутствующие плагины аналогами LYNX SHARE в Опции › Общие настройки..., по умолчанию оно включено. Если оно выключено, слот отсутствующего эффекта выпадает из микшера. Отсутствующий инструмент не заменяется. Он становится встроенным синтезатором с пресетом, выбранным по имени канала.

Чтобы вернуть настоящий плагин, установите его, выберите Опции › Поиск плагинов, затем снова откройте проект.

Файл › Открыть... создает новый проект из файла MIDI. Файл › Импорт › Файл MIDI... сначала открывает окно Импорт данных MIDI, где вы выбираете, что принести.

Что стоит знать

  • Справка › Отсутствующие файлы... снова открывает окно позже. Справка › Last FL Studio import report перечисляет, что было приближено, пропущено или не установлено.
  • Клипы сессии из сета Live попадают в сетку клипов раскладки Clip-launch. Клипы сессии из сетов Live в Опции › Общие настройки... размещает их вместо этого в Playlist.
