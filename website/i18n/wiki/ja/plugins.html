LYNX SHAREは、ほかのメーカーのインストゥルメントとエフェクトのプラグインをホストできます。プラグインフォルダーをスキャンして見つけ、オプション › プラグインマネージャー... に見つかったものが表示されます。LYNX SHARE独自のインストゥルメントとエフェクトについては、内蔵のインストゥルメントとエフェクトで説明しています。

プラグインをスキャンして追加する

  1. オプション › プラグインをスキャン を選びます。進行状況はヒントバーに表示され、作業を続けられます。
  2. プラグインが専用のフォルダーにある場合は、オプション › プラグインマネージャー... を開いて プラグインフォルダー... をクリックし、そのフォルダーを追加してから 新しいプラグインを検索 をクリックします。
  3. F8 を押してプラグインピッカーを開き、プラグイン名の一部を入力します。
  4. ダブルクリックするか、Enter を押します。インストゥルメントは新しいチャンネルになります。エフェクトは、選択中のミキサーのインサートに入ります。

初回起動時には、セットアップウィザードがプラグインフォルダーを一覧にして、バックグラウンドでスキャンします。オプション › セットアップウィザード (言語、オーディオ、プラグインフォルダー)... で、もう一度開けます。LYNX SHAREは、起動のたびに数秒後、新しいプラグインも探します。

プラグインファイルは、1つずつ別プロセスで調べられます。クラッシュしたファイルや、30秒止まったままのファイルは、失敗としてマークされ、以後はスキップされます。Windowsでは、失敗したファイルが理由とともに %APPDATA%\LYNX\scan-failures.log に一覧で残ります。

標準のフォルダーに加えて、追加したフォルダーがスキャンされます。

  • Windows: Common Files\VST3、Common Files\CLAP、Common Files\VST2、Program Files内の VSTPlugins と Steinberg\VSTPlugins。FL Studioがインストールされていれば、FL Studioが使うフォルダーも含まれます。
  • macOS: ~/Library/Audio/Plug-Ins と /Library/Audio/Plug-Ins にある VST3、Components、CLAP。
  • Linux: ~/.vst3、~/.clap、~/.lv2、~/.vst、および /usr/lib と /usr/local/lib の下の同じフォルダー。

ドッキングしたプラグインウィンドウと独立したプラグインウィンドウ

プラグインのエディターは、ほかのパネルと同じようにメインウィンドウの中で開きます。プラグインウィンドウのメニューにある 切り離し を選ぶと、そのプラグインは専用のウィンドウになります。同じメニューの 手前に固定 を選ぶと、独立したウィンドウがLYNX SHAREのほかのウィンドウより前面に残ります。

オプション › 全般設定... の 新しいプラグインをすべて切り離す をオンにすると、追加するプラグインがすべて独立したウィンドウで開きます。ツール › すべてのプラグインエディターを切り替え では、プロジェクトのすべてのプラグインを ドッキング か 切り離し にまとめて切り替えられます。

プラグインを別プロセスで実行する

初期設定では、プラグインはLYNX SHAREの中で動くので、クラッシュしたプラグインがプログラムごと落とすことがあります。オプションを使うと、プラグインごとに専用のプロセスで動かせます。

  1. オプション › 全般設定... を開きます。
  2. プラグインを別プロセスで実行 (クラッシュからLYNX SHAREを保護) をオンにします。
  3. すでに開いているプラグインに反映するには、プロジェクトを開き直します。

このようなプラグインがクラッシュしたり応答しなくなったりすると、ミュートされてメッセージが表示され、LYNX SHAREは動き続けます。メッセージの 再読み込み を押すと、プロジェクトを開き直さずに、最後の保存またはバックアップの設定でそのプラグインが再び起動します。プラグインのエディターは専用のウィンドウで開き、ドッキングやピン留めはできません。

1つのプラグインだけに適用するには、プラグインウィンドウのラッパーメニューにある 別プロセスで実行 または Always run <plugin> in a separate process を使います。プラグインのエディターがクラッシュしたときに出るメッセージにも、後者が表示されます。

この機能は、WindowsとLinuxで動き、0.1.25からはmacOSでも動きます。

LYNX SHARE内でクラッシュしたプラグインはオフになり、そのメッセージにも 再読み込み があります。あとからは、チャンネルのメニューかエフェクトスロットのメニューにある クラッシュしたプラグインを再読み込み を使います。

32ビットプラグイン (Windowsのみ)

Windowsでは、32ビットのVST2とVST3のプラグインは、ブリッジ (LYNX-bridge32.exe) を通して動きます。ブリッジによるレイテンシーの増加はありません。ブリッジの中でクラッシュしたプラグインは単独で止まり、LYNX SHAREは再生を続けます。ブリッジ経由のプラグインのエディターは専用のウィンドウで開き、ドッキングやピン留めはできません。プラグインの32ビット版と64ビット版の両方がインストールされている場合は、プラグインウィンドウの ラッパー設定 にある ビット数 で、読み込む方を選びます。

インストゥルメントの出力を別々のインサートに送る

複数の出力を持つインストゥルメントプラグインは、出力ごとに別のミキサーインサートで鳴らせます。プラグインのウィンドウで ラッパー設定 をクリックし、処理 タブを開きます。接続 の下に、出力ごとにオン/オフのライトと数字があります。数字は、チャンネル自身のインサートから数えて何番目あとのインサートで鳴らすかを表します。出力を自動マップ は各出力に次のインサートを順に割り当て、リセット は既定に戻します。

Plugin databaseフォルダー

ブラウザーのPlugin databaseのフォルダー、プラグインピッカー、プラグインのメニューは、ディスク上の1つのフォルダー、つまりドキュメントフォルダー内の LYNX/Plugin database です。開くには、ブラウザーで プラグインデータベース を右クリックして 開く を選びます。

  • エフェクト と ジェネレーター には、プラグイン1つにつき1つの .lynxplugin ファイルがあります。フォルダーとサブフォルダー (最大4階層) を作って、ファイルを移せます。
  • ファイル名を変えると、メニューでのプラグイン名が変わります。ファイルを削除すると、そのプラグインがメニューから消えます。アンインストールはされません。
  • インストール済み には、すべてのプラグインの項目があります。プラグインを元に戻すには、その項目を エフェクト か ジェネレーター にコピーします。

プラグインなしでプロジェクトを開く

ファイル › サードパーティ製プラグインなしで開く... は、サードパーティ製のプラグインをすべてオフにしてLYNX SHAREのプロジェクトを開きます。開けないプロジェクトや、読み込み中にクラッシュするプロジェクト向けです。プラグインの保存済みの設定は残ります。ファイル › プラグインをオンに戻す... で、もう一度オンにできます。

プラグインがインストールされていないとき

LYNX SHAREは、まず識別子、次にファイル、次に名前で、同じプラグインを探します。VST2で保存したプロジェクトは同じ製品のVST3で開け、その逆も同様ですが、その場合プラグインはデフォルトの設定で鳴ります。

エフェクトがまったくインストールされていない場合は、同じ役割のLYNX SHAREのエフェクトがそのスロットに入り、元のプラグインはプロジェクトに残ります。プラグインの保存済みの設定が読み取れる場合は、代わりのエフェクトも対応する設定で始まります。切り替えは、オプション › 全般設定... の 見つからないプラグインをLYNX SHAREの同等品で代替 です。内蔵のインストゥルメントとエフェクトを参照してください。置き換えられたプラグインは、ヘルプ › 見つからないファイル... に一覧で出ます。

知っておくと便利なこと

  • ホストしたプラグインのウィンドウには、プリセットバーがあります。プラグイン自身のプログラム、ユーザーのプリセット、プリセットを保存...、プリセットファイルを読み込む...、プリセットファイルをエクスポート... です。.fxp、.fxb、.vstpreset ファイルは、LYNX SHAREの中で動くプラグインにだけ読み込めます。別プロセスで動くプラグインには読み込めません。
  • モニターが計測するのは、そのウィンドウが開いている間だけです。
  • プラグインのウィンドウにフォーカスがあるとき、プラグインが使わないキーは、タイピングキーボードのピアノを鳴らします。Windowsでは、ウィンドウのヘッダーにあるキーボードボタンがオフの場合、LYNX SHAREがショートカットを含め、プラグインより先にキーを処理します。
  • VST3プラグイン自身のパラメーターメニューは、オートメーションクリップを作成 など、LYNX SHAREの項目から始まります。オートメーションを参照してください。
  • プラグインの ラッパー設定 にある MIDI の下の MPE を使うと、ノートごとに別のMIDIチャンネルで送られます。MIDIコントローラーを参照してください。
  • 見つからないインストゥルメントの代替は、まだありません。見つからないインストゥルメントのプラグインは、チャンネル名から選ばれた内蔵シンセになります。
