以下の見出しは、1つが1つの問題です。見つからない場合は、最後に書いてある方法で報告してください。

プログラムの起動

Windows: 初回起動時にSmartScreenが警告する

実行ファイルにはまだコード署名がないため、初めて実行するときにSmartScreenが警告を出すことがあります。

  1. More info をクリックします。
  2. Run anyway をクリックします。

インストーラーに管理者権限は不要です。

macOS: 「開けません」と表示される

このアプリはAppleによる公証を受けておらず、Developer IDの署名もないため、初回起動には追加の手順が1つ必要です。

  1. LYNX SHAREを Applications にドラッグします。
  2. 右クリック (またはControlキーを押しながらクリック) して、開く を選びます。
  3. もう一度 開く をクリックします。

macOS 15 Sequoia以降では、一度開こうとしてから、System Settings › Privacy & Security へ進み、Open Anyway をクリックします。または、ターミナルで次を実行します。

xattr -dr com.apple.quarantine /Applications/LYNX.app

初めて録音するときに、macOSがマイクへのアクセスを尋ねます。

Linux: AppImageが起動しない

LYNX SHAREには、glibc 2.35以降のx86_64システム (Ubuntu 22.04、Debian 12、Fedora 36、最新のArchまたはManjaro) と、X11またはXWaylandが必要です。

  1. 下の2つのコマンドで、ファイルを実行可能にして実行します。
  2. それでも起動しない場合は、libfuse2をインストールします。パッケージ名は、Ubuntu 22.04では libfuse2、Ubuntu 24.04では libfuse2t64、Archでは fuse2、Fedoraでは fuse-libs です。
  3. インストールしたくない場合は、代わりに .tar.gz をダウンロードして展開し、./install.sh を実行します。
chmod +x LYNX-*.AppImage
./LYNX-*.AppImage

./install.sh は、メニュー項目とともに、~/.local の下に現在のユーザー用としてLYNX SHAREをインストールします。./install.sh --uninstall で削除します。

サウンド

音が出ない、またはオーディオデバイスが違う

  1. オプション › オーディオ設定... を開きます。
  2. ドライバーを選びます。
  3. 出力デバイスを選びます。
システムドライバー
WindowsWindows Audio (WASAPI)、DirectSound、ASIO、内蔵のLYNX ASIOドライバー
macOSCore Audio
LinuxPipeWire (ネイティブ)、JACK、ALSA。初回起動時は、LYNX SHAREがこの中でデバイスのある最初のものを開く

ASIOはWindowsのドライバーモデルで、Windowsにしかありません。オプション › セットアップウィザード (言語、オーディオ、プラグインフォルダー)... でも、オーディオデバイスをテストできます。オーディオの設定を参照してください。

Linux: 音が途切れる

オーディオスレッドは、リアルタイム優先度で動かす必要があります。

  1. オプション › オーディオ設定... を開いて、状態 を読みます。スレッドがリアルタイム優先度を得たかどうかが表示されます。
  2. 得られていない場合は、rtkitをインストールします (sudo apt install rtkit、sudo dnf install rtkit、または sudo pacman -S rtkit)。あるいは、JACKの環境と同じように、リアルタイムの制限付きで自分を オーディオ グループに追加します。
  3. 一度ログアウトして、ログインし直します。

詳細はLINUX.mdにあります。

プラグイン

プラグインがクラッシュする

専用のプロセスで実行すると、止まるのはそのプラグインだけになります。

  1. オプション › 全般設定... を開きます。
  2. プラグインを別プロセスで実行 (クラッシュからLYNX SHAREを保護) をオンにします。
  3. プロジェクトを開き直します。

専用のプロセスでクラッシュしたり、応答しなくなったりしたプラグインは、ミュートされます。プロジェクトを保存して開き直すと、そのプラグインが再び読み込まれます。サードパーティのプラグインを参照してください。

プラグインが一覧にない

  1. オプション › プラグインをスキャン を選びます。
  2. それでも見つからない場合は、オプション › プラグインマネージャー... を開き、プラグインフォルダー... をクリックして、そのプラグインのフォルダーを追加します。
  3. 失敗 タブを見ます。スキャンに失敗したプラグインファイルは、スキップされます。Windowsでは、理由が %APPDATA%\LYNX\scan-failures.log に書かれています。
  4. すべて再スキャン... をクリックすると、失敗したファイルをもう一度試します。

プロジェクトがインストールされていないプラグインを使っている

エフェクトは、同じ役割のLYNX SHAREのエフェクトに置き換えられ、その設定はプロジェクトに残ります。ヘルプ › 見つからないファイル... に、足りないものが一覧で出ます。内蔵のインストゥルメントとエフェクトを参照してください。

Linuxでビデオが動かない

ビデオトラックと Export with video には、FFmpegが必要です。インストール方法は、LYNX SHAREが案内します。

クラッシュレポート

クラッシュレポートは、オプトインです。クラッシュやフリーズのあと、次の起動時に、レポートを送るかどうかを尋ねます。

コマンド働き
送信内容を表示送信される文面そのままを表示する
代わりにGitHubで報告GitHubのイシューフォームを、入力済みの状態で開く。ファイルは自分で添付する
レポートのフォルダーを開くレポートのファイルを、お使いのコンピューター上で表示する
Include file names (projects, samples)オフのときは、各ファイルの拡張子だけが送られる
確認せずに常に送信以後のレポートを、確認なしで送る

オプション › 全般設定... の クラッシュレポート で、Ask (初期設定)、常に送信、送信しない を選べます。

レポートには、LYNX SHAREのバージョン、オペレーティングシステム、CPU、グラフィックスカードとそのドライバー、画面サイズ、オーディオドライバーとデバイス、クラッシュまたはフリーズのファイル、セッションの直近60ステップ、読み込まれていたサードパーティのプラグインの名前とバージョンが含まれます。

オーディオ、プロジェクト、サンプル、お使いのコンピューターの名前、ユーザー名は含まれません。サーバーはIPアドレスを保存しません。送信したIDは、設定フォルダーの crash-reports\sent.log に一覧で残ります。レポートの削除を依頼するには、そのIDを添えてイシューを立ててください。全文はプライバシーポリシーにあります。

問題を報告する

  1. ヘルプ › 問題を報告... を選びます。
  2. 何が起きたかを説明します。メールアドレスは任意で、返信が欲しいときに入力します。
  3. 問題がクラッシュだった場合は、最新のクラッシュ / フリーズファイルとこのセッションのステップを添付 にチェックを入れたままにします。
  4. 送信内容を表示 をクリックして、文面を確認します。
  5. 送る をクリックします。それまでは何も送信されません。

github.com/Ka1-S/LYNX-SHARE/issuesでイシューを立てることもできます。

知っておくと便利なこと

  • クラッシュのあとは、プロジェクトのバックアップコピーが、LYNX SHAREの自動保存フォルダーにあります。
  • クラッシュにプラグインが関わっていた場合は、確認の画面で、以後そのプラグインを別プロセスで実行するかどうかを選べます。
  • 設定フォルダーは、Windowsでは %APPDATA%\LYNX、macOSでは ~/Library/Application Support/LYNX、Linuxでは ~/.config/LYNX です。
