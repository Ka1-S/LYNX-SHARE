LYNX SHARE 可以承载其他厂商的乐器和效果器插件。它通过扫描插件文件夹来找到它们，`选项 › 插件管理器...` 会显示它找到了什么。LYNX SHARE 自己的乐器和效果器在[内置乐器和效果器](/wiki/built-in/)中介绍。

## 扫描并添加插件

1. 选择 `选项 › 扫描插件`。进度显示在提示栏中，你可以继续工作。
2. 如果插件在它自己的文件夹中，请打开 `选项 › 插件管理器...`，单击 `插件文件夹...`，添加该文件夹，然后单击 `查找新插件`。
3. 按 `F8` 打开插件选择器，输入插件名称的一部分。
4. 双击它或按 `Enter`。乐器会变成新通道。效果器会进入所选的混音台插入轨。

首次启动时，设置向导会列出插件文件夹，并在后台扫描它们。`选项 › 设置向导（语言、音频、插件文件夹）...` 可再次打开它。每次启动几秒钟后，LYNX SHARE 也会查找新插件。

## 各系统的格式

| 系统 | 承载的格式 |
|---|---|
| Windows | VST3、CLAP、VST2 |
| macOS | VST3、CLAP、Audio Units |
| Linux | VST3、CLAP、LV2、VST2 |

macOS 上不承载 VST2。在 Linux 上，Windows 插件可通过 [yabridge](https://github.com/robbert-vdh/yabridge) 和 Wine 使用，二者需要你自己安装：把 yabridge 同步到的文件夹添加为插件文件夹。

## 插件管理器

| 控件 | 作用 |
|---|---|
| 搜索框 | 按名称、厂商、格式或文件筛选 |
| `全部`、`乐器`、`效果器`、`收藏`、`失败` | 选择列出哪些插件 |
| 星标列 | 标记收藏 |
| `位数` 列 | 32、64 或 32+64（Windows） |
| `状态` 列 | `确定`、`未找到文件` 或 `加载失败` |
| `查找新插件` | 扫描列表中还没有的文件 |
| `全部重新扫描...` | 忘掉失败的文件，并重新检查每一个文件 |
| `插件文件夹...` | 编辑被扫描的文件夹 |
| `添加插件文件...` | 添加单个插件文件 |

每个插件文件都在独立进程中检查。崩溃或卡住 30 秒的文件会被标记为失败，之后会被跳过。在 Windows 上，失败的文件及原因列在 `%APPDATA%\LYNX\scan-failures.log` 中。

标准文件夹会被扫描，外加你添加的文件夹：

- Windows：`Common Files\VST3`、`Common Files\CLAP`、`Common Files\VST2`，以及 Program Files 下的 `VSTPlugins` 和 `Steinberg\VSTPlugins`，如果安装了 FL Studio，还有它使用的文件夹。
- macOS：`~/Library/Audio/Plug-Ins` 和 `/Library/Audio/Plug-Ins` 中的 `VST3`、`Components` 和 `CLAP`。
- Linux：`~/.vst3`、`~/.clap`、`~/.lv2`、`~/.vst`，以及 `/usr/lib` 和 `/usr/local/lib` 下的同名文件夹。

## 停靠和分离的插件窗口

插件的编辑器像其他面板一样在主窗口内打开。插件窗口菜单中的 `已分离` 会给该插件一个独立窗口，同一菜单中的 `固定在最前` 会让分离的窗口保持在 LYNX SHARE 其他窗口之上。

`选项 › 常规设置...` 中的 `分离所有新插件` 会让你添加的每个插件都以分离方式打开。`工具 › 将所有插件编辑器切换为` 可把工程中所有插件设为 `已停靠` 或 `已分离`。

## 在独立进程中运行插件

默认情况下，插件在 LYNX SHARE 内部运行，所以崩溃的插件可能拖垮整个程序。作为一个选项，可以让每个插件在自己的进程中运行。

1. 打开 `选项 › 常规设置...`。
2. 打开 `在独立进程中运行插件（防止插件崩溃影响LYNX SHARE）`。
3. 重新打开工程，使其对已经打开的插件生效。

如果这样的插件崩溃或停止响应，它会被静音，并出现一条消息，LYNX SHARE 则继续运行。该消息中的 `重新加载` 会用上次保存或备份的设置重新启动该插件，无需重新打开工程。插件的编辑器在它自己的窗口中打开，不能停靠或固定。

如果只想对某一个插件这样做，请使用插件窗口封装器菜单中的 `在独立进程中运行` 或 `Always run <plugin> in a separate process`。当插件的编辑器崩溃时，出现的消息里也提供第二个选项。

这在 Windows 和 Linux 上可用，自 0.1.25 起 macOS 上也可用。

在 LYNX SHARE 内部崩溃的插件会被关闭，它的消息中同样有 `重新加载`。之后可以使用通道菜单或效果器插槽菜单中的 `重新加载已崩溃的插件`。

## 32 位插件（仅限 Windows）

在 Windows 上，32 位的 VST2 和 VST3 插件通过桥接程序（`LYNX-bridge32.exe`）运行。桥接不会增加延迟。在其中崩溃的插件会自行停止，而 LYNX SHARE 继续播放。桥接插件的编辑器在它自己的窗口中打开，不能停靠或固定。当一个插件同时安装了 32 位和 64 位版本时，插件窗口 `封装器设置` 中的 `位数` 决定加载哪一个。

## 插件性能监视器

![插件性能监视器：每个乐器和效果器占一行，显示其占用的处理时间份额](/assets/img/wiki/plugin-monitor.webp)

`工具 › 插件性能监视器...` 列出每个乐器和效果器所占用的处理时间：当前值、平均值和峰值。100% 表示在音频持续的整段时间里，一个处理器核心一直处于忙碌状态。

| 设置 | 作用 |
|---|---|
| `查找` | 按插件、通道或插入轨筛选 |
| `仅插件` | 隐藏 LYNX SHARE 自己的乐器和效果器 |
| `冻结` | 停止更新数字 |
| `播放时重置` | 每次开始播放时重新计算平均值和峰值 |
| `重置` | 立即清除平均值和峰值 |

## 把乐器的输出送到不同的插入轨

有多个输出的乐器插件可以让每个输出在各自的混音台插入轨上播放。在插件窗口中，单击 `封装器设置`，再单击 `处理` 选项卡。在 `连接` 下，每个输出都有一个用来开关它的指示灯和一个数字：表示它在通道自己的插入轨之后的第几个插入轨上播放。`自动映射输出` 会给每个输出分配下一个插入轨，`重置` 则恢复默认值。

## 插件数据库文件夹

[浏览器](/wiki/browser/)的插件数据库、插件选择器和插件菜单中的文件夹，都对应磁盘上的一个文件夹：文档文件夹中的 `LYNX/Plugin database`。要打开它，请在浏览器中右键单击 `插件数据库`，然后选择 `打开`。

- `效果器` 和 `发生器` 里每个插件有一个 `.lynxplugin` 文件。可以新建文件夹和子文件夹（最多 4 层），再把文件移进去。
- 重命名文件即可在菜单中重命名插件。删除文件即可把插件从菜单中去掉，但不会卸载它。
- `已安装` 里有每个插件的条目。把其中一个复制到 `效果器` 或 `发生器`，即可找回该插件。

## 不加载插件打开工程

`文件 › 不加载第三方插件打开...` 会在关闭所有第三方插件的情况下打开 LYNX SHARE 工程，适用于打不开或加载时崩溃的工程。插件已保存的设置会保留。`文件 › 重新开启插件...` 会重新打开它们。

## 插件没有安装时

LYNX SHARE 先按标识符查找同一个插件，然后按文件，再按名称。以 VST2 保存的工程可以用同一产品的 VST3 打开，反过来也一样，但此时插件使用默认设置播放。

如果某个效果器完全没有安装，一个作用相同的 LYNX SHARE 效果器会占据它的插槽，而原插件仍保留在工程中。如果能读取插件已保存的设置，替身会以相应的设置启动。开关是 `选项 › 常规设置...` 中的 `用LYNX SHARE对应插件替代缺失的插件`。见[内置乐器和效果器](/wiki/built-in/)。`帮助 › 缺失的文件...` 会列出被替换的插件。

## 须知

- 被承载插件的窗口有一个预设栏：插件自己的程序、你的预设、`保存预设...`、`加载预设文件...` 和 `导出预设文件...`。`.fxp`、`.fxb` 和 `.vstpreset` 文件只能加载到在 LYNX SHARE 内部运行的插件中，不能加载到在独立进程中运行的插件。
- 监视器只在它的窗口打开时才测量。
- 插件窗口获得焦点时，插件不用的按键会弹奏打字键盘钢琴。在 Windows 上，如果窗口标题栏中的键盘按钮关闭，LYNX SHARE 会先于插件处理按键，包括快捷键。
- VST3 插件自己的参数菜单以 LYNX SHARE 的菜单项开头，例如 `创建自动化片段`。见[自动化](/wiki/automation/)。
- 插件 `封装器设置` 中 `MIDI` 下的 `MPE` 会让每个音符在自己的 MIDI 通道上发送。见 [MIDI 控制器](/wiki/midi-controllers/)。
- 缺失的乐器目前不做替代。缺失的乐器插件会变成按通道名称选定的内置合成器。
