设置窗口的音频页面用来选择声音从哪里输出，以及录音从哪里输入。用 `选项 › 音频设置...` 打开。设置向导（`选项 › 设置向导（语言、音频、插件文件夹）...`）也会测试音频输出。

## 让声音出来

1. 打开 `选项 › 音频设置...`。
2. 选择一个 `驱动程序`。下拉框下方的说明会告诉你这种驱动程序适合什么情况。
3. 选择一个 `输出设备`。
4. 点击 `播放测试音`。
5. 查看 `状态` 部分。它会显示正在运行的驱动程序、采样率和输出延迟，或者显示 `未打开音频设备：请选择输出设备。`。

## 驱动程序

`驱动程序` 下拉框列出你系统上的驱动程序类型。

| 系统 | 驱动程序 | 作用 |
|---|---|---|
| Windows | Windows音频（共享） | 其他程序的声音不受影响。Windows 以固定步长混合所有程序的声音，所以缓冲区不能小于这个步长 |
| Windows | Windows音频（共享，低延迟周期） | 仍是共享模式，但会向 Windows 请求更短的混合周期。只有部分驱动程序支持 |
| Windows | Windows音频（独占，最低延迟） | LYNX SHARE 独占设备。播放时其他程序没有声音 |
| Windows | DirectSound（旧版） | 旧的 Windows 音频通道，延迟高。其他方式都不行时再用 |
| Windows | ASIO | 低延迟驱动程序。厂商的 ASIO 驱动程序配合它自己的设备使用 |
| Windows | LYNX ASIO（内置） | LYNX SHARE 自带的 ASIO 驱动程序，适用于任何设备，支持播放和录音。`驱动程序设置...` 用来选择共享或独占模式以及设备 |
| macOS | Core Audio | 系统自带的音频，与其他程序共享 |
| Linux | PipeWire（原生） | LYNX SHARE 直接与 PipeWire 通信。`System default` 跟随系统声音设置中选择的输出 |
| Linux | JACK / PipeWire | 用于正在运行的 JACK 服务器，或装有 `pipewire-jack` 的 PipeWire |
| Linux | ALSA | 直接与声卡通信。`default` 或 `pipewire` 共享设备，`hw:` 设备则让 LYNX SHARE 独占声卡 |

在 Linux 上，首次启动时会打开 PipeWire、JACK、ALSA 中第一个有设备的驱动程序。保存过的选择会保留。

## 页面上的设置

| 设置 | 作用 |
|---|---|
| `驱动程序` | 驱动程序类型，见上表 |
| `输出设备` | 主控从哪里播放 |
| `输入设备` | 音频录制和混音台插入轨输入的来源。默认为 `（无）` |
| `采样率` | 设备提供的采样率 |
| `缓冲区大小` | 设备提供的缓冲区大小，每个都标有以毫秒计的延迟。缓冲区越小，演奏时响应越快。缓冲区越大，CPU 的余量越多，爆音也越少 |
| `驱动程序设置...` | 打开驱动程序自己的窗口（ASIO 驱动程序） |
| `播放测试音` | 通过输出设备播放测试音 |
| `录制输入音频` | 没有预备任何插入轨时，把前两个输入通道录入一个新的插入轨 |
| `文件格式` | 录音为 WAV 24 位或 WAV 32 位浮点，采样率与设备相同 |
| `测量往返延迟` | 通过线缆或回环，从 `Ping输出` 向 `Ping输入` 播放 8 次咔嗒声，并测量延迟，让录音落在你演奏的位置 |
| `微调（采样）` | 移动每一条新录音。正值表示在播放列表上更靠前 |
| `节拍器轨道` | 节拍器经过的混音台轨道。`---` 表示主控。节拍声永远不会出现在导出文件里 |
| `走带时播放被截断的音符` | 播放跨越起始位置的音符 |
| `走带时重置插件` | 播放开始或跳转时清除效果器的尾音 |

## 没有声音时

- 先看 `状态`。如果没有打开任何设备，请选择一个输出设备。
- 换一个驱动程序试试。在 Windows 上，`Windows音频（共享）` 可以让其他程序保留声音，而 `DirectSound（旧版）` 是在其他方式都不行时使用的。
- 检查[混音台](/wiki/mixer/)中的主控推子，以及工具栏中的 `主控` 旋钮。
- 在样式模式下，只会播放当前样式。如果它是空的，就什么也听不到。按 `L` 切换到歌曲模式。
- 在 Linux 上，如果声音断断续续，`状态` 会显示音频线程是否获得了实时优先级。解决办法见[故障排除](/wiki/troubleshooting/)。

## 须知

- ASIO 只存在于 Windows。
- 使用 `Windows音频（共享）` 时，最小缓冲区就是系统的混合步长。`驱动程序` 下拉框下方的说明会给出你的设备的具体数值。要获得更低的延迟，请使用独占模式或 ASIO 驱动程序。
- 使用 PipeWire 时，缓冲区范围是 32 到 2048 个采样，采样率范围是 44.1 到 192 kHz。如果 PipeWire 保持自己的采样率，它会对 LYNX SHARE 的音频流重新采样。
- 使用 PipeWire 时，如果拔掉了指定名称的设备，LYNX SHARE 会回退到 `System default`，并保持缓冲区大小不变。
- `状态` 还会显示音频 CPU 负载，并统计掉帧次数（缓冲区欠载）。
- 不打开窗口也可以列出驱动程序和设备。见[命令行](/wiki/command-line/)中的 `--devices`。
