LYNX SHAREは、ほかのメーカーのインストゥルメントとエフェクトのプラグインをホストできます。プラグインフォルダーをスキャンして見つけ、`オプション › プラグインマネージャー...` に見つかったものが表示されます。LYNX SHARE独自のインストゥルメントとエフェクトについては、[内蔵のインストゥルメントとエフェクト](/wiki/built-in/)で説明しています。

## プラグインをスキャンして追加する

1. `オプション › プラグインをスキャン` を選びます。進行状況はヒントバーに表示され、作業を続けられます。
2. プラグインが専用のフォルダーにある場合は、`オプション › プラグインマネージャー...` を開いて `プラグインフォルダー...` をクリックし、そのフォルダーを追加してから `新しいプラグインを検索` をクリックします。
3. `F8` を押してプラグインピッカーを開き、プラグイン名の一部を入力します。
4. ダブルクリックするか、`Enter` を押します。インストゥルメントは新しいチャンネルになります。エフェクトは、選択中のミキサーのインサートに入ります。

初回起動時には、セットアップウィザードがプラグインフォルダーを一覧にして、バックグラウンドでスキャンします。`オプション › セットアップウィザード (言語、オーディオ、プラグインフォルダー)...` で、もう一度開けます。LYNX SHAREは、起動のたびに数秒後、新しいプラグインも探します。

## システム別の形式

| システム | ホストできる形式 |
|---|---|
| Windows | VST3、CLAP、VST2 |
| macOS | VST3、CLAP、Audio Units |
| Linux | VST3、CLAP、LV2、VST2 |

macOSでは、VST2はホストできません。Linuxでは、ご自身でインストールした[yabridge](https://github.com/robbert-vdh/yabridge)とWineを通して、Windowsのプラグインが動きます。yabridgeが同期するフォルダーを、プラグインフォルダーとして追加してください。

## プラグインマネージャー

| コントロール | 働き |
|---|---|
| 検索ボックス | 名前、ベンダー、形式、ファイルで絞り込む |
| `すべて`、`インストゥルメント`、`エフェクト`、`お気に入り`、`失敗` | 一覧に表示するプラグインを選ぶ |
| スター列 | お気に入りの印を付ける |
| `ビット` 列 | 32、64、または32+64 (Windows) |
| `状態` 列 | `OK`、`ファイルなし`、`読み込み失敗` |
| `新しいプラグインを検索` | 一覧にまだないファイルをスキャンする |
| `すべて再スキャン...` | 失敗したファイルの記録を消して、すべてのファイルをもう一度調べる |
| `プラグインフォルダー...` | スキャンするフォルダーを編集する |
| `プラグインファイルを追加...` | プラグインファイルを1つ追加する |

プラグインファイルは、1つずつ別プロセスで調べられます。クラッシュしたファイルや、30秒止まったままのファイルは、失敗としてマークされ、以後はスキップされます。Windowsでは、失敗したファイルが理由とともに `%APPDATA%\LYNX\scan-failures.log` に一覧で残ります。

標準のフォルダーに加えて、追加したフォルダーがスキャンされます。

- Windows: `Common Files\VST3`、`Common Files\CLAP`、`Common Files\VST2`、Program Files内の `VSTPlugins` と `Steinberg\VSTPlugins`。FL Studioがインストールされていれば、FL Studioが使うフォルダーも含まれます。
- macOS: `~/Library/Audio/Plug-Ins` と `/Library/Audio/Plug-Ins` にある `VST3`、`Components`、`CLAP`。
- Linux: `~/.vst3`、`~/.clap`、`~/.lv2`、`~/.vst`、および `/usr/lib` と `/usr/local/lib` の下の同じフォルダー。

## プラグインを別プロセスで実行する

初期設定では、プラグインはLYNX SHAREの中で動くので、クラッシュしたプラグインがプログラムごと落とすことがあります。オプションを使うと、プラグインごとに専用のプロセスで動かせます。

1. `オプション › 全般設定...` を開きます。
2. `プラグインを別プロセスで実行 (クラッシュからLYNX SHAREを保護)` をオンにします。
3. すでに開いているプラグインに反映するには、プロジェクトを開き直します。

このようなプラグインがクラッシュしたり応答しなくなったりすると、ミュートされてメッセージが表示され、LYNX SHAREは動き続けます。プロジェクトを保存して開き直すと、そのプラグインが再び読み込まれます。プラグインのエディターは、専用のウィンドウで開きます。

1つのプラグインだけに適用するには、プラグインウィンドウのラッパーメニューにある `別プロセスで実行` または `Always run <plugin> in a separate process` を使います。プラグインのエディターがクラッシュしたときに出るメッセージにも、後者が表示されます。

この機能は、WindowsとLinuxで動き、0.1.25からはmacOSでも動きます。

## 32ビットプラグイン (Windowsのみ)

Windowsでは、32ビットのVST2とVST3のプラグインは、ブリッジ (`LYNX-bridge32.exe`) を通して動きます。ブリッジによるレイテンシーの増加はありません。ブリッジの中でクラッシュしたプラグインは単独で止まり、LYNX SHAREは再生を続けます。ブリッジ経由のプラグインのエディターは、専用のウィンドウで開きます。プラグインの32ビット版と64ビット版の両方がインストールされている場合は、プラグインウィンドウの `ラッパー設定` にある `ビット数` で、読み込む方を選びます。

## プラグインパフォーマンスモニター

![プラグインパフォーマンスモニター: インストゥルメントとエフェクトごとに1行で、処理時間に占める割合を表示する](/assets/img/wiki/plugin-monitor.webp)

`ツール › プラグインパフォーマンスモニター...` には、すべてのインストゥルメントとエフェクトが、現在、平均、ピークの処理時間とともに一覧で出ます。100%は、オーディオの長さの間ずっと、プロセッサーコア1つが使われていることを意味します。

| 設定 | 働き |
|---|---|
| `検索` | プラグイン、チャンネル、インサートで絞り込む |
| `プラグインのみ` | LYNX SHARE独自のインストゥルメントとエフェクトを非表示にする |
| `フリーズ` | 数値の更新を止める |
| `再生時にリセット` | 再生を始めるたびに、平均とピークをやり直す |
| `リセット` | 平均とピークを今すぐクリアする |

## プラグインがインストールされていないとき

LYNX SHAREは、まず識別子、次にファイル、次に名前で、同じプラグインを探します。VST2で保存したプロジェクトは同じ製品のVST3で開け、その逆も同様ですが、その場合プラグインはデフォルトの設定で鳴ります。

エフェクトがまったくインストールされていない場合は、同じ役割のLYNX SHAREのエフェクトがそのスロットに入り、元のプラグインはプロジェクトに残ります。[内蔵のインストゥルメントとエフェクト](/wiki/built-in/)を参照してください。置き換えられたプラグインは、`ヘルプ › 見つからないファイル...` に一覧で出ます。

## 知っておくと便利なこと

- ホストしたプラグインのウィンドウには、プリセットバーがあります。プラグイン自身のプログラム、ユーザーのプリセット、`プリセットを保存...`、`プリセットファイルを読み込む...`、`プリセットファイルをエクスポート...` です。`.fxp`、`.fxb`、`.vstpreset` ファイルは、LYNX SHAREの中で動くプラグインにだけ読み込めます。別プロセスで動くプラグインには読み込めません。
- モニターが計測するのは、そのウィンドウが開いている間だけです。
- 見つからないインストゥルメントの代替は、まだありません。見つからないインストゥルメントのプラグインは、チャンネル名から選ばれた内蔵シンセになります。
