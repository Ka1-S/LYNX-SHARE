## Запуск программы

### Windows: SmartScreen предупреждает при первом запуске

Исполняемый файл пока не подписан цифровой подписью, поэтому при первом запуске SmartScreen может выдать предупреждение.

1. Нажмите `More info`.
2. Нажмите `Run anyway`.

Для установщика не нужны права администратора.

### macOS: «не удается открыть»

Приложение не нотаризовано Apple и не имеет подписи Developer ID, поэтому при первом запуске нужен один дополнительный шаг.

1. Перетащите LYNX SHARE в `Applications`.
2. Щелкните его правой кнопкой (или с Control) и выберите `Открыть`.
3. Нажмите `Открыть` еще раз.

В macOS 15 Sequoia или новее попробуйте открыть программу один раз, затем перейдите в `System Settings › Privacy & Security` и нажмите `Open Anyway`. Или в Терминале:

```
xattr -dr com.apple.quarantine /Applications/LYNX.app
```

macOS запрашивает доступ к микрофону при первой записи.

### Linux: AppImage не запускается

LYNX SHARE нужна система x86_64 с glibc 2.35 или новее (Ubuntu 22.04, Debian 12, Fedora 36, актуальный Arch или Manjaro) и X11 или XWayland.

1. Сделайте файл исполняемым и запустите его двумя командами ниже.
2. Если он по-прежнему не запускается, установите libfuse2. Пакет называется `libfuse2` в Ubuntu 22.04, `libfuse2t64` в Ubuntu 24.04, `fuse2` в Arch и `fuse-libs` в Fedora.
3. Если вы не хотите его устанавливать, скачайте вместо этого `.tar.gz`, распакуйте его и запустите `./install.sh`.

```
chmod +x LYNX-*.AppImage
./LYNX-*.AppImage
```

`./install.sh` устанавливает LYNX SHARE для вашего пользователя в `~/.local` с пунктом меню. `./install.sh --uninstall` удаляет его.

## Звук

### Нет звука или выбрано не то аудиоустройство

1. Откройте `Опции › Настройки аудио...`.
2. Выберите драйвер.
3. Выберите устройство вывода.

| Система | Драйверы |
|---|---|
| Windows | Windows Audio (WASAPI), DirectSound, ASIO и встроенный драйвер LYNX ASIO |
| macOS | Core Audio |
| Linux | PipeWire (нативный), JACK и ALSA. При первом запуске LYNX SHARE открывает первый из них, у которого есть устройства |

ASIO — модель драйверов Windows и существует только в Windows. `Опции › Мастер настройки (язык, аудио, папки плагинов)...` тоже проверяет аудиоустройство. См. [Настройка звука](/wiki/audio-setup/).

### Linux: звук прерывается

Аудиопоток должен работать с приоритетом реального времени.

1. Откройте `Опции › Настройки аудио...` и прочитайте `Статус`. Там видно, получил ли поток приоритет реального времени.
2. Если нет, установите rtkit (`sudo apt install rtkit`, `sudo dnf install rtkit` или `sudo pacman -S rtkit`) либо добавьте себя в группу `audio` с лимитом реального времени, как в конфигурациях JACK.
3. Выйдите из системы и войдите снова.

Подробности есть в [LINUX.md](https://github.com/Ka1-S/LYNX-SHARE/blob/main/docs/LINUX.md).

## Плагины

### Плагин падает

Запустите его в собственном процессе, чтобы останавливался только плагин.

1. Откройте `Опции › Общие настройки...`.
2. Включите `Запускать плагины в отдельном процессе (защищает LYNX SHARE от сбоев)`.
3. Откройте проект заново.

Плагин, который упал или перестал отвечать в собственном процессе, заглушается. Сохраните проект и откройте его снова, чтобы загрузить плагин заново. См. [Сторонние плагины](/wiki/plugins/).

### Плагина нет в списке

1. Выберите `Опции › Поиск плагинов`.
2. Если его все равно нет, откройте `Опции › Менеджер плагинов...`, нажмите `Папки плагинов...` и добавьте папку плагина.
3. Посмотрите вкладку `С ошибкой`. Файл плагина, не прошедший сканирование, пропускается. В Windows причина записана в `%APPDATA%\LYNX\scan-failures.log`.
4. Нажмите `Сканировать все...`, чтобы попробовать неудачные файлы еще раз.

### Проект использует плагин, который не установлен

Эффект заменяется эффектом LYNX SHARE с той же ролью, а его настройки остаются в проекте. `Справка › Отсутствующие файлы...` перечисляет, чего не хватает. См. [Встроенные инструменты и эффекты](/wiki/built-in/).

### Видео не работает в Linux

Для видеодорожек и `Export with video` нужен FFmpeg. LYNX SHARE подскажет, как его установить.

## Отчеты о сбоях

![Вопрос об отчете о сбое при следующем запуске, с кнопками отправки, показа отправляемого и отказа](/assets/img/wiki/crash-report.webp)

Отчеты о сбоях отправляются только по вашему согласию. После сбоя или зависания при следующем запуске программа спрашивает, отправлять ли отчет.

| Команда | Что делает |
|---|---|
| `Показать, что будет отправлено` | Показывает точный текст |
| `Сообщить на GitHub` | Открывает форму issue на GitHub, уже заполненную. Файлы вы прикладываете сами |
| `Открыть папку с отчетом` | Показывает файлы отчета на вашем компьютере |
| `Include file names (projects, samples)` | Если выключено, отправляется только расширение каждого файла |
| `Всегда отправлять без вопросов` | Отправляет будущие отчеты без вопроса |

`Отчеты о сбоях` в `Опции › Общие настройки...` задает `Ask` (по умолчанию), `Всегда отправлять` или `Никогда не отправлять`.

Отчет содержит версию LYNX SHARE, операционную систему, процессор, видеокарты и их драйверы, размер экрана, аудиодрайвер и устройство, файл сбоя или зависания, последние 60 шагов сеанса, а также имена и версии загруженных сторонних плагинов.

В нем нет аудио, проектов, сэмплов, имени вашего компьютера и имени пользователя. Сервер не хранит IP-адреса. Отправленные идентификаторы перечислены в `crash-reports\sent.log` в папке настроек. Чтобы отчет удалили, откройте issue с его идентификатором. Полный текст находится в [политике конфиденциальности](https://github.com/Ka1-S/LYNX-SHARE/blob/main/PRIVACY.md).

## Сообщение о проблеме

![Окно сообщения о проблеме: поле описания, необязательный адрес e-mail и кнопка отправки](/assets/img/wiki/report-problem.webp)

1. Выберите `Справка › Сообщить о проблеме...`.
2. Опишите, что произошло. Адрес e-mail указывать необязательно, он нужен, если вы хотите получить ответ.
3. Оставьте флажок `Приложить последние файлы сбоев / зависаний и шаги этого сеанса` отмеченным, если проблема была в сбое.
4. Нажмите `Показать, что будет отправлено`, чтобы проверить текст.
5. Нажмите `Отправить`. До этого ничего не отправляется.

Можно также открыть issue на [github.com/Ka1-S/LYNX-SHARE/issues](https://github.com/Ka1-S/LYNX-SHARE/issues).

## Что стоит знать

- После сбоя резервные копии вашего проекта лежат в папке автосохранений LYNX SHARE.
- Если в сбое участвовал плагин, в вопросе предлагается запускать этот плагин в отдельном процессе в дальнейшем.
- Папка настроек — `%APPDATA%\LYNX` в Windows, `~/Library/Application Support/LYNX` в macOS и `~/.config/LYNX` в Linux.
